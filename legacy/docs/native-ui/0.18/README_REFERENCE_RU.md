# TACTIC 5.0 — Vue Source Fork 0.18

**Полный исходный форк на основе реально выпущенной 0.17.** Предыдущие отчёты об ошибке упаковки 0.18 не используются как исходники или доказательство реализации. В этой рабочей копии редакторы созданы заново, сохранены промежуточные архивы и выполнены проверки. Ядро остаётся `5.0.0.a02`; Vue — включённая ранее `3.5.13`, не утверждение о последней версии. Готовая сборка включена, Node для обычного запуска не нужен.

Этот этап: **Custom Layout, Manage Views, Ace и запуск сохранённых Python-скриптов, дополнительные инструменты Manage sTypes, начало/выполнение/завершение запросов в консоли**. Sidebar и точки входа берутся из оригинальных widget_config, а не фиксированного списка страниц. Нет новой прикладной БД или самостоятельной модели SObject.

## 1. Обновление

**Не удаляйте `local_data`; INIT, SETUP и UPGRADE ради этого выпуска повторять не нужно.** Сохраните резервную копию, остановите всю прежнюю группу и распакуйте 0.18 отдельно. Из НОВОГО каталога `TACTIC-5.0`, подставив свои реальные пути:

```bat
set "TACTIC_PYTHON=D:\TACTIC_OLD\TACTIC-5.0\.runtime\python\python.exe"
set "DATA=D:\TACTIC_OLD\TACTIC-5.0\local_data"
START_CLUSTER.bat --data-dir "%DATA%" --port 9123 --workers 3
```

Для одного процесса: `START_TACTIC.bat --data-dir "%DATA%" --port 9123`. При внешней конфигурации сохраните свой `--config`. Адрес: `http://127.0.0.1:9123/tactic/admin/`. После обновления Ctrl+F5. Остановка группы — Ctrl+C. Все прежние BAT и загрузчик окружения сохранены; изменён только Python-helper `CONFIGURE_NATIVE` для нового отдельного переключателя скриптов. Пакет не содержит Python runtime и ваши базы.

Разрешения из `<data-dir>/config/native-ui.json` продолжают действовать. Поставка по умолчанию не разрешает запись. Для её включения на остановленной тестовой установке:

```bat
CONFIGURE_NATIVE.bat --data-dir "%DATA%" --writes on
```

Команда требует `ENABLE`. Загрузка файлов — отдельный `--uploads on`. Запуск сохранённого Python — ещё один отдельный переключатель, по умолчанию **выключен**:

```bat
CONFIGURE_NATIVE.bat --data-dir "%DATA%" --writes on --scripts on
```

После изменения перезапустить сервер. `--scripts off` отключает выполнение без запрета редактировать сохранённый код. `--writes off` также выключает uploads и выполнение Python. Вход native UI всё ещё только административный; это не релиз поддержки всех обычных ролей.

## 2. Custom Layout Editor

Штатный `CustomLayoutEditWdg` больше не направляется в общий XML-экран. Отдельный Vue-редактор открывает **реальные записи `config/widget_config` категории CustomLayoutWdg**, общие и собственные персональные. Есть каталог с поиском/страницами, создание, явная копия, удаление выбранного override, исходный XML, экспорт XML и открытие сохранённого layout.

Секции: **HTML, CSS, Mako, kwargs, behavior, callback**. CSS хранится в исходном `html/style`, а не в независимом поле новой таблицы. Behavior/callback редактируются как XML-блоки с кодом внутри CDATA. `kwargs` принимает JSON-объект или dictionary literal без выполнения eval. Валидный XML обязателен; неоднозначные дубли, внешние сущности и DTD отвергаются.

Сохранение изменяет только выбранные секции или выбранный view. Соседние views, неизвестные узлы/атрибуты, комментарии и нетронутые CDATA сохраняются. Проверяется ревизия всей записи: конфликт не стирает черновик. Удаление убирает выбранный override, не исходное представление нижнего слоя; оно может вновь стать видимым. Работа идёт через оригинальные Search/SObject и Command-транзакцию, не прямую запись SQL из браузера. Это новый транспорт секционных правок, не побайтовая копия старого callback сборки XML.

### Предпросмотр и вложенные виджеты

**Предпросмотр статический. Mako, `[expr]`, пользовательские behaviors/callbacks и JavaScript не исполняются.** Они сохраняются для исходной конфигурации и legacy, но не выдаются за полностью перенесённую динамическую среду.

HTML/CSS показываются в ограниченном Shadow DOM; script, event handlers, внешние URL и потенциально активные CSS-конструкции не применяются. Произвольные HTML-контролы в этом preview не являются работающими формами. При сомнительной CSS-строке — диагностика, а не молчаливое выполнение. Это не универсальный браузер или эмулятор MooTools.

**В сохранённом layout** исходные `<element>` открывают настоящие поддержанные native-виджеты через WidgetHost. Поддержаны inline display, `display_class` с атрибутами, определения элементов того же view, ссылки `type=reference` на разрешённый SearchType/view, относительные имена вложенных layout. Отсутствующий display не превращается в случайную таблицу. `display=false`/`load=none` не открывают скрытый виджет даже по прямому derived URL.

Порядок runtime-поиска: category в БД, затем указанные исходные include-файлы, затем поддержанный deprecated search_type=CustomLayoutWdg. Include разрешён только внутри штатного каталога UI-конфигураций; произвольные серверные файлы не читаются. Равноприоритетные неоднозначные записи требуют выбора конкретного источника. Учитывается область shared/own; чужие персональные записи не раскрываются.

`load=manual/sequence/async`, `load_once`, исполнение динамических блоков, все внешние plugin callbacks и legacy-запись только `<html>` без `<config>` ещё не перенесены. До 64 вложенных элементов, прежний предел глубины target — 8. Документ до 4 МиБ, секция до 1 МиБ; oversized данные не обрезаются и не перезаписываются.

## 3. Script Editor

Подключён **Ace 1.4.7, уже поставляемый внутри исходного TACTIC**: подсветка Python/JavaScript/XML/HTML/CSS, поиск, сворачивание, undo/redo, Ctrl+S, светлая и тёмная темы. Рабочие ресурсы обслуживаются самим TACTIC, без CDN. Worker Ace отключён. Если редактор не загрузился, доступен текстовый fallback с явным сообщением.

Каталог и сохранение остались на `config/custom_script` через исходные insert/update. Текст не форматируется при сохранении. Добавлен diff **сохранённый текст → текущий черновик** с проверкой ревизии. Это не журнал всех прошлых версий, а сравнение с текущей записью БД.

### Запуск сохранённого Python

Нужны исходное право Script Editor, разрешение записи и `allow_script_execution=true`. Исполняется только **активная сохранённая Python-запись** по ключу/ревизии и однозначному folder/title. Текст кода из POST не принимается. Несохранённый черновик нельзя выполнить; перед запуском отдельное подтверждение.

Команда — исходный `TacticServerStub.execute_python_script` / PythonCmd. JSON-параметры передаются как исходный `input`. Результат сохраняет оригинальный конверт TACTIC, например `result.info`, и показывается в редакторе. Параметры ограничены 32 КиБ UTF-8, код — прежними 256 КиБ, возвращаемый JSON — 256 КиБ. Большой результат не означает, что код нужно повторно запускать.

**Это НЕ песочница.** Python имеет права серверного процесса и может менять базы, файлы и внешние системы. Синтаксическая проверка не доказывает безопасность кода. Выполнение синхронное: долгое выполнение занимает ведущую очередь записи. HTTP timeout не гарантирует остановку Python. После ошибки/потери ответа повтор заблокирован в текущем редакторе; сначала проверить журнал и данные. Exactly-once при ручном повторе, rollback внешних эффектов и жёсткий time limit не заявляются.

Запуск JavaScript/server_js/expression, полноценный debugger, breakpoint и просмотр полной истории скрипта не перенесены. Сохранённые скрипты могут использоваться существующими workflow даже при выключенной новой кнопке Run.

## 4. Manage Views

Отдельный каталог исходных представлений выбранного SearchType: разрешённые file/default views и конкретные shared/personal DB-слои. Можно выбрать источник, создать новый table-view, скопировать конкретный view, открыть конфигурационный редактор элементов/параметров, редактировать XML, открыть итоговый виджет и удалить выбранное переопределение.

При копировании конкретной записи копируется **только выбранный view**, не весь документ с соседними представлениями. При копировании разрешённого унаследованного представления создаётся явно обозначенный snapshot его текущих элементов/атрибутов/опций. Это намеренная копия, не автоматическое изменение исходных defaults. Неизменённый source view не перезаписывается.

При XML-save сохраняются остальные views исходной DB-записи. Неоднозначные имена и конфликты ревизии дают отказ, черновик остаётся. Смена SearchType и переходы защищены от потери несохранённого XML и позднего ответа старого запроса. Открытие идёт по разрешённому layout-handler: таблица, EditWdg, TabWdg либо диагностика неперенесённого обработчика. Все views не превращаются принудительно в TableLayoutWdg.

Editor остаётся на оригинальном `widget_config`, а не новом JSON-формате. JSON — транспорт. Полная динамическая компиляция любого layout не заявляется. Переименование существующего view и автоматическое обновление всех ссылок на него здесь не включены: доступна явная копия и отдельное удаление override.

## 5. Manage sTypes

Сохранены создание типа, исходные формы, метаданные, ColumnEditCbk/ColumnAddCmd и определения колонок. Добавлены:

- переходы к исходной таблице, форме создания SObject, workflow, схеме и Manage Views именно выбранного типа;
- переход к определению конкретной колонки, а не только всей длинной definition;
- сохранение выбранного SearchType и раздела через оригинальный WidgetSettings, с проверкой разрешённых типов; черновики не сохраняются как предпочтения;
- чтение кандидатов ссылок на колонку/тип в config/widget_config, custom_script, trigger, client_trigger, process и реальных отношений Schema;
- ограниченный CSV-импорт новых записей через **оригинальный CsvImportCmd**.

### CSV

CSV UTF-8 до 1 МиБ, 100 строк данных, 30 колонок; comma/semicolon/tab. Заголовок сопоставляется с разрешёнными существующими обычными полями. ID/code, системные, password и поля со специальными form actions не принимаются. Поля не создаются. Предпросмотр ничего не записывает и показывает исходное CSV-преобразование: пробелы по краям обрезаются, некоторые control-символы удаляются; пустая ячейка не является NULL.

После подтверждения повторно проверяются input, схема и ревизия конфигурации, затем в исходной Command-транзакции выполняется CsvImportCmd с включёнными серверными триггерами. Temp-файл создаётся сервером и удаляется после операции; клиент не передаёт произвольный путь. CSV-команда не является EditWdg и не выполняет все его form actions — поэтому импорт ограничен обычными полями. Нет обновления существующих строк по ID, импорта заметок, подавления триггеров и автоматического повтора при неопределённом результате. Полный legacy CSV wizard ещё не перенесён.

### Что НЕ объявляется завершённым

**Удаление/переименование/смена типа существующих физических колонок и полный Triggers/Notifications editor в этом выпуске не реализованы.** Просмотр ссылок — кандидаты в конфигурации текущего проекта, не доказательство отсутствия зависимостей. Внешние скрипты, другие проекты и динамически построенные выражения могут ссылаться на поле. Деструктивная операция не разблокируется только из-за пустого результата этого анализа. Лимит анализа — 1000 записей каждого проверяемого config-типа; превышение обозначается, не обрезается молча.

## 6. Консоль во время запроса

Сохраняется журнал safe actions каждого worker и общий вывод группы. Добавлены **START**, **RUNNING** и **END**:

- START появляется при разборе запроса до ожидания backend-lock; есть request_id, пользователь/проект и безопасное описание;
- для запроса, который продолжается более пяти секунд, периодически появляется RUNNING с прошедшим временем, состоянием и известными исходными командами;
- END показывает результат, HTTP status, длительность, количества строк/ячеек и реальные команды. Нормальное окончание и ошибка различаются.

START не означает успешную запись. Вызов действия UI не означает commit. RUNNING не доказывает, что зависший вызов делает полезную работу; это признак незавершённого запроса. При смерти worker END может отсутствовать; группа не повторяет такую запись автоматически.

Для неожиданных исключений добавлены последние module/function/line **без текста локальных переменных, исходных строк и значения исключения**. Пароли, tickets, cookies, тела скриптов/XML/CSV, параметры input и значения SObject новый safe-журнал не копирует. Исходные private worker-логи могут содержать более подробный вывод самого TACTIC — не публикуйте их как безопасные.

По умолчанию `TACTIC_ACTION_LOG=actions`; `verbose` включает успешные служебные опросы, `off` выключает новый диагностический журнал. Ошибки в actions-режиме остаются видимыми. Запросы UI-состояния/health не создают постоянный поток START в обычном режиме. Ротация и места хранения прежние. Пример фактически выполненного шестисекундного Python-запроса находится в `docs/native-ui/0.18/validation/console-example.txt`.

## 7. Проверки и границы доказательств

Фактические завершённые результаты — `docs/native-ui/0.18/validation/summary.json`, внешний `TACTIC_5_Vue_0.18_Verification.json` и логи отдельных наборов. Старые отчёты 0.2–0.17 остаются историческими. Неудачные промежуточные попытки не прибавляются к успешным проверкам.

Unit-проверки исполняют реальные методы и изолированные конфигурации; они не приравниваются к живой БД. Сквозной runner создаёт **полные временные копии штатных SQLite seed**, выполняет исходные обновления и запускает три настоящих процесса TACTIC. Пароль/ticket, Search/SObject, команды, транзакции и запись настоящие. Только подпись лицензии явно изолирована тестовым флагом; рабочий сервер эту проверку не отключает.

Браузер сначала пробует прямую навигацию. При запрете средой применяется явный HTTP-мост. Он доставляет реальные HTTP-ответы, локальные Ace assets и CSS; не заменяет данные/сохранение фиктивным backend. Однако **нативные cookies/CSP/navigation/WebCrypto так не доказаны**. Скриншоты помечены original SQLite/test data/signature isolation/bridge. Windows BAT/PowerShell, загрузка runtime, PostgreSQL/MySQL, все пользовательские plugins и external effects здесь не проверены.

Повторение в developer-окружении:

```bat
python -W ignore -m unittest discover -s tests/native_ui -v
node tests/native_ui/test_design_state_018.cjs
node tools/native_ui/build.cjs
python tools/native_ui/audit_config_parity.py --out config-parity.json
python tests/native_ui/run_cluster_018.py --output D:\TEMP\tactic018-test --chromium C:\path\chrome.exe
```

`--isolate-license` только в изолированном CI без криптографических зависимостей; `--bridge` только после запрета прямой навигации. Рабочие START_* таких тестовых флагов не принимают. Runner не принимает путь к рабочей БД и не использует пользовательские данные.

## 8. Состав и откат

Полный форк, готовые JS/CSS и локальный Ace, прежние BAT, тесты, source map и patch к .17. Не включены `.runtime`, .git, caches/pyc, пользовательские или private test базы/конфиги, raw worker logs, testdeps, test payload и font files. Оригинальные seed-базы сохранены побайтно. Состав и хеши перечислены в release manifest.

`START_LEGACY.bat` меняет рендерер, но не отменяет сохранённые XML, скрипты, CSV-записи или правила доступа. Возврат исходников — из 0.17; возврат данных — из своей резервной копии. Старые `tactic/ui`, `pyasm/widget`, `pyasm/web` **не удалять**: полный перенос всех динамических/специализированных виджетов, обычных ролей и headless-ядра продолжается.
