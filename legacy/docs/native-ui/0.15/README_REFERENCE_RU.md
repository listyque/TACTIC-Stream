# TACTIC 5.0 — Vue source fork 0.15

Полный исходный форк на основе выпущенной **0.14**. Версия ядра остаётся `5.0.0.a02`; Vue — прежний `3.5.13`, готовая сборка из 41 SFC включена. Новых библиотек и миграции существующих пользовательских баз для обновления интерфейса нет.

Этот этап: **рабочий мастер создания проекта и переход в него; удаление дублирующих заголовков обычных таблиц; сохранение настроек интерфейса в оригинальной БД TACTIC**. Sidebar, типы представлений, исходные поля и обработчики не заменены отдельной моделью приложения.

## 1. Обновление

Не удалять `local_data`, не выполнять INIT заново, не повторять SETUP/UPGRADE ради этого выпуска. Сначала остановить ВСЮ группу TACTIC и сохранить резервную копию своих данных. Распаковать 0.15 отдельно. Из НОВОГО каталога `TACTIC-5.0`, подставив реальные старые рабочие Python и данные:

```bat
set "TACTIC_PYTHON=D:\TACTIC_OLD\TACTIC-5.0\.runtime\python\python.exe"
set "DATA=D:\TACTIC_OLD\TACTIC-5.0\local_data"
START_CLUSTER.bat --data-dir "%DATA%" --port 9123 --workers 3
```

Для одного процесса — `START_TACTIC.bat --data-dir "%DATA%" --port 9123`. Если использовался внешний XML, сохранить свой аргумент `--config`. Адрес `http://127.0.0.1:9123/tactic/admin/`. После обновления — Ctrl+F5. Node для обычного запуска не нужен. Остановка — Ctrl+C в окне запуска группы.

Все BAT, runtime manifest, установщик окружения и исходные seed-базы сохранены. Рабочие разрешения берутся из `<data-dir>/config/native-ui.json`, не сбрасываются новой версией. При выключенной записи UI-параметры читаются, но новые настройки и проекты не записываются. Для осознанного включения на остановленной тестовой установке:

```bat
CONFIGURE_NATIVE.bat --data-dir "%DATA%" --writes on
```

Требуется подтверждение `ENABLE`. Uploads включаются отдельно. Пользовательские БД, Python и конфиги не входят в архив. Сохранены прежние CHECK_ENV, CHECK_STARTUP, CHECK_LOCAL_DB, RESTORE и offline-upgrade.

## 2. Мастер создания проекта

Конфигурационная ссылка Create Project / ProjectCreateWdg открывает настоящий поэтапный Vue-виджет:

1. Название, код и описание проекта.
2. Поддержанный исходный тип: `default` либо `simple`.
3. Предварительная проверка имени проекта/базы, итоговые параметры и выбор перехода.
4. Результат и кнопка открытия созданного проекта.

Переход назад не теряет введённые данные. До окончательного подтверждения проект не создаётся. При изменении параметров токен предварительной проверки становится недействительным. Блокируются системные/некорректные коды, уже зарегистрированные проекты, включая архивные, и существующие базы без новой регистрации. Произвольные пути файлов, имена Python-классов или внешние базы не принимаются.

Создание идёт через подкласс **оригинального `CreateProjectCmd`**. Его последовательность создания проекта, базы, исходной схемы/данных и sidebar сохранена. Дополнения относятся к подготовке НОВОЙ SQLite-базы и проверке результата. Существующий project database не перестраивается этим endpoint.

### Исправленная причина падения SQLite

Первоначально импортированный `config_schema.sql` создавал, например, `spt_widget_config`, тогда как реестр `sthpw/search_object` ожидал `widget_config`. Последующий исходный импорт sidebar не находил нужное хранилище.

Теперь в только что созданной базе штатные config-таблицы согласуются с реальными именами реестра. Не создаётся второе параллельное пустое хранилище вместо существующего. Применяются исходные upgrade-классы через ранее введённый SQLite-адаптер, проверяются ошибки, обязательная структура, идентификаторы и integrity_check. Sidebar создаётся в контексте нового проекта. В конце восстанавливается контекст исходного запроса и stub.

После успеха обновляется список проектов, переключается активный проект, перечитывается ЕГО sidebar и меняется адрес `/tactic/<project>/`. Проверено без перезапуска и при работе трёх workers. Открытие нативной HTML-страницы требует обычного браузерного `Accept: text/html`; сервисные маршруты и legacy/XML-RPC не подменяются этой страницей.

### Ограничения мастера

- Пока поддержаны исходные `default` и `simple`. Это не импорт любого зарегистрированного template-project. Preview проекта, смена theme/palette в мастере и произвольные шаблоны не представлены как готовые функции.
- DDL, создание файлов и исходные промежуточные commit не являются единой гарантированно обратимой транзакцией. При ошибке проект может оказаться частично создан. Автоматического удаления, повтора или восстановления таких проектов нет. Интерфейс предупреждает проверить Projects/логи; совпадающий код не перезаписывается.
- Потерянный HTTP-ответ не доказывает, что проект не создался. Повторный клик и автоматический retry заблокированы при неопределённом результате.
- Ранее частично созданные проекты предыдущих версий автоматически не исправляются. Не удалять их базы без проверки данных.
- PostgreSQL/MySQL сохраняют исходную ветку CreateProjectCmd/Upgrade; их создание в этом выпуске не проверено.

## 3. Настройки — настоящая БД TACTIC

В production-коде больше нет вызовов localStorage/sessionStorage. Персональные параметры читаются и записываются через **оригинальный `pyasm.web.WidgetSettings` в `sthpw/wdg_settings`**, с исходными login/project и серверным site-контекстом. Новая таблица UI-параметров не создавалась. Сессии балансировщика остаются отдельным прежним транспортным хранилищем — оно не используется для UI-предпочтений.

| Что сохраняется | Область |
|---|---|
| Открытые основные представления и активная вкладка | Пользователь + проект |
| Тема | Пользователь + проект |
| Раскрытие папок sidebar | Пользователь + проект + исходные folder IDs |
| Фильтры AND/OR, сортировка, архивный режим, offset/limit, вид отображения, открытие поиска и поля быстрого фильтра | Пользователь + проект + настроенный target |
| Ширина, порядок, закрепление, видимость колонок, плотность, перенос текста, локальная группировка | Пользователь + проект + target таблицы |
| Вложенные TabWdg: порядок, выбранная/закрытые вкладки и их собственные названия | Пользователь + проект + target контейнера, по исходным именам дочерних элементов |
| Период/месяц Gantt/календаря, масштаб, поля дат, режим без дат | Пользователь + проект + target таблицы |

Обычные и вложенные таблицы используют одно хранилище параметров. Смена порядка колонок НЕ меняет схему данных. Настройки результата поиска не подменяют обязательный исходный фильтр view или ограничение родительского объекта. `set_persistent_search=false` проекта запрещает native-сохранение последнего поиска. При недопустимости сохранённых параметров для новой конфигурации выдаётся предупреждение; исходная запись в БД не удаляется молча.

### Совместимость с legacy — точная граница

Оригинальный `WidgetSettings` используется для storage/API. Native-состояние имеет **отдельные namespaced ключи `native:ui:v1:*` и JSON-envelope**. Оно не перезаписывает старые `last_search:*` / XML `save_state` другой структуры. Именованные сохранённые поиски и редактор представлений по-прежнему используют настоящий **`config/widget_config`**.

Это совместимость хранилища и исходной модели, **не обещание побайтовой идентичности сериализованных настроек native и MooTools UI**. Не происходит автоматического импорта всех прежних локальных предпочтений браузера 0.14 или всех legacy-ключей. При отсутствии новой DB-записи используются исходные настройки view; последующие изменения сохраняются в БД. Существующие именованные поиски/представления из widget_config остаются доступными.

В исходном `WidgetSettings.get_by_key` исправлен ключ request-cache: он теперь включает site, project и login, а не только login. Это предотвращает смешение параметров, если один исходный запрос временно сменил проект. SQL-модель и прежние публичные методы не заменены.

### Сохранение и конфликты

Запись объединяется debounce 300 мс; один запрос на канал выполняется за раз. Перед сменой проекта/выходом ожидается завершение очереди. Ревизия сравнивается с полученной серверной. Запоздалый ответ открытой ранее таблицы или восстановления её настроек проверяется по проекту, target и поколению навигации: он не записывает старое состояние в новый проект. Закрытые виджеты также отбрасывают такие ответы. При конфликте/обрыве нет скрытого retry поверх чужих изменений: показывается ошибка, состояние нужно перечитать. Серверные команды проходят прежнюю транзакционную обёртку; флаг read-only не обходится.

В группе GET UI-параметров балансируется между workers, PATCH идёт через существующую ведущую очередь. Настройки переживают новый вход/новый браузер и не зависят от временной native-cookie или run-id группы. При нескольких независимых серверах либо прямых параллельных внешних редакторах глобальная serializable/CAS-гарантия не заявляется.

**Не сохраняются** наборы полученных SObject-записей, значения несохранённых полей, пароли, tickets и черновики форм. Общее Save Changes остаётся отдельной явной записью через EditMultipleCmd. DB-предпочтения не превращают набранную правку в сохранённый объект.

Пределы: 32 основные вкладки, 64 вкладки контейнера, 64 КиБ JSON на канал, до 256 имён колонок, 1024 folder overrides. Только разрешённые исходной конфигурацией поля/вкладки; скрытый child или защищённое закрытие не становятся доступны через state endpoint.

## 4. Таблицы без дублирующего заголовка

Удалён большой заголовок обычной таблицы под основной вкладкой, а также повторный h3 у вложенной WidgetTable. Название остаётся во вкладке/контексте; у контейнера есть доступное aria-label. **Заголовки колонок, их меню, сортировка и ресайз не удалены.** Компактная панель 0.13, меню 0.14, Fill и общий буфер сохранены.

Точные числа и статусы — `docs/native-ui/0.15/validation/summary.json` и внешний Verification JSON. Предыдущие документы остаются историческими отчётами, не заново выполненными тестами.

Новый сквозной набор создаёт default/simple проекты на оригинальном сервере с полными временными SQLite seed, затем SearchType и SObject в новом проекте. Проверяются реальный пароль/ticket, команды, исходная регистрация sidebar, URL HTML-страницы, состояние в WidgetSettings, конфликты и независимость проектов. Нативные настройки дополнительно прочитаны через исходный XML-RPC `get_widget_setting`; отдельный legacy-ключ не меняется при записи native-параметров.

Три настоящих worker PID обслуживают общую установку. Проверены чтение нового проекта каждым worker, распределённое чтение UI-параметров, повторное чтение после записи, замена процессов и штатное завершение. Браузерный сценарий намеренно запрещает localStorage/sessionStorage: после выхода и создания нового браузерного контекста восстанавливаются таблица, поиск, сортировка, ширины, закрепление, плотность, тема и sidebar.

**Подпись тестовой лицензии изолирована только явным тестовым флагом; production её не отключает.** SQL/аутентификация/команды не подменены fixture-объектами. Прямая навигация Chromium блокируется средой; явно использован HTTP-мост, поэтому native cookies/CSP/navigation/WebCrypto им не доказаны. Серверные HTTP-запросы остаются настоящими. Windows BAT/PowerShell и PostgreSQL/MySQL в этой среде не запускались. Скриншоты помечены original TACTIC / SQLite test data / isolated signature / bridge.

Один исторический browser-тест закрывал меню кликом по теперь удалённому h1. В новой регрессии изменён только его якорь на кнопку активной вкладки; целевое отсутствие большого заголовка проверяется отдельным сценарием.

```bat
python -W ignore -m unittest discover -s tests/native_ui -v
node tests/native_ui/test_ui_state_015.cjs
node tools/native_ui/build.cjs
python tools/native_ui/audit_config_parity.py --out config-parity.json
python tests/native_ui/run_cluster_015.py --output D:\TEMP\tactic015-test --chromium C:\path\chrome.exe
```

`--isolate-license` — только для изолированного CI без криптографии, `--bridge` — только при реальном запрете навигации. Runner создаёт собственную временную установку, не принимает рабочие данные. Он не заменяет START_CLUSTER.

## 6. Состав и пределы

Полный source fork, готовые JS/CSS, BAT, патч к 0.14, source map, тесты и отфильтрованные результаты. Не включены .runtime, рабочие/частные тестовые базы и конфиги, сырые worker-логи с tickets, caches/pyc/.git и файлы шрифтов. Исходные seed-базы сохранены побайтно.

Вход пока admin-only. Не заявляется полный перенос всех шаблонов проектов, произвольных callbacks/виджетов, review/planner, multi-site/multi-machine или всех прав обычных пользователей. Старые UI-каталоги остаются нужны. START_LEGACY переключает рендерер, но **не откатывает данные**. Для возврата исходников — предыдущий архив, данных/файлов — собственная резервная копия.
