# TACTIC 5.0 — native Vue source fork 0.12

Основа: полный архив **TACTIC_5_Vue_Source_Fork_1.1.zip**, который по принятой нумерации считаем **0.11**. Теперь `NATIVE_UI_VERSION=0.12`; исходная версия ядра `5.0.0.a02` не меняется. Это **реальный полный форк с готовой сборкой**, не макет и не накладка. Неудавшаяся предыдущая сборка 0.12 не использована как готовая основа: изменения сделаны и проверены в чистом дереве последнего выпущенного архива.

Этот этап меняет обычную таблицу: исходные определения виджетов, отдельный inline-редактор, буфер нескольких строк, общее сохранение, реальные previews и современная светлая/тёмная тема. **Полный перенос каждого произвольного legacy-виджета не завершён.**

## 1. Обновить работающую установку

**Не удалять local_data. Не выполнять INIT заново. Для изменений 0.12 не нужны новые SETUP или UPGRADE.** Ранее требовавшийся ремонт SERIAL-ключей из 0.11 остаётся действующим требованием: если вы ещё не выполнили его, используйте прежний CHECK_LOCAL_DB и описанную процедуру. Новых миграций в этом этапе нет.

Сохраните резервную копию своей тестовой установки и остановите старый сервер. Распакуйте архив отдельно. Команды выполняются из НОВОГО корня `TACTIC-5.0`:

```bat
set "TACTIC_PYTHON=D:\TACTIC_OLD\TACTIC-5.0\.runtime\python\python.exe"
set "DATA=D:\TACTIC_OLD\TACTIC-5.0\local_data"
START_TACTIC.bat --data-dir "%DATA%" --port 9123
```

Пути — примеры: подставьте свои уже работающие Python и данные; они могут находиться в разных каталогах. При внешней XML-конфигурации сохраните прежний `--config "путь\tactic-conf.xml"`. Откройте `http://127.0.0.1:9123/tactic/admin/`; при старом кэше обновите страницу Ctrl+F5. Остановка — Ctrl+C.

Vue уже собран в `src/tactic/ui_api/web`. Node/npm нужны только для пересборки, не обычного запуска. Все существующие BAT (`SETUP_ENV`, `CHECK_ENV`, `CHECK_STARTUP`, `CHECK_LOCAL_DB`, `CONFIGURE_NATIVE`, `START_TACTIC`, `START_LEGACY`, INIT/UPGRADE/RESTORE_LOCAL_SQLITE, `BUILD_VUE`) сохранены побайтно. Загрузчик окружения не изменялся; Windows и доступность его загрузок заново не проверены.

Настройки чтения/записи сохраняются в `<data-dir>/config/native-ui.json`, а не сбрасываются при обновлении исходников. Если запись ещё не разрешена, при остановленном сервере:

```bat
CONFIGURE_NATIVE.bat --data-dir "%DATA%" --writes on
START_TACTIC.bat --data-dir "%DATA%" --port 9123
```

Потребуется подтверждение `ENABLE`. Для check-in отдельно разрешается `--uploads on`. Поставка `src/tactic/ui_api/config.json` по-прежнему read-only; существующий выбранный конфиг данных переопределяет его. Не включайте запись на production без проверки на копии. Вход пока только администраторам. `START_LEGACY.bat` возвращает прежний рендерер, **не откатывает записанные данные**. Старые UI-каталоги не удалять.

## 2. Таблица: отображение, редактор, сохранение — разные механизмы

Sidebar, исходные таблицы, формы, представления и их порядок остаются на `config/widget_config`, XML типа проекта, персональных/общих definitions и DEFAULT. В этом этапе не созданы альтернативные таблицы приложения и фиксированные модели.

### Display-ячейка

`values` содержит исходные значения; `cells` — разрешённую сервером проекцию display-виджета. Форматированная строка, display name или цвет не записываются обратно как значение поля. Сохраняются исходные FormatElementWdg, явные column aliases, ссылки, XML и специальные вложенные виджеты предыдущего этапа.

Добавлены представления для явно объявленных `LoginTableElementWdg` (логин → display_name, пакетная выборка), `TaskStatusElementWdg` (цвет исходного task/process pipeline, не фиксированный словарь статусов по названию поля) и `pyasm.widget.ColorWdg` (цветовой образец). Неизвестный обработчик не угадывается по названию колонки. Значения для CSS ограничены безопасными литералами. Ошибка определения цвета не превращается в выдуманный статус.

### CellEditWdg

Двойной щелчок/F2/Enter получает **собственное определение ячейки**, не обычную popup EditWdg-форму целиком. Новый `tactic.core.cell_edit_config` следует исходному `CellEditWdg.init` из `layout_wdg.py`:

1. Некэшированное разрешение `edit`.
2. Inline `config_xml` / edit configuration.
3. DB-переопределение `edit_item` с исходным приоритетом.

Сохранено и неочевидное поведение original WidgetDbConfig: его `get_handler` возвращает display-handler независимо от аргумента type. Для `edit_item` редактор может объявляться в `<display class="…"/>`, а параметры вводимого элемента — в `<edit>…</edit>`. Это сверяется с реально исполненным телом original CellEditWdg, не исправлено «по интуиции».

Параметры редактора, включая строки textarea, берутся из конфигурации. Зависимые параметры строки повторно разрешаются сервером с учётом уже набранных значений, **без записи в БД**. Для сохранения отдельно воспроизводится исходный lookup `EditCmd` (обычно view `edit_item`, inline edit и соответствующие action/options). Popup создания/редактирования продолжает использовать собственный EditWdg, не этот resolver.

## 3. Буфер и Save Changes

**Применить в ячейке ≠ сохранить в БД.** Изменённые ячейки подсвечены; сверху показываются число ячеек и строк, кнопки «Отменить» и «Сохранить изменения». Буфер хранится в памяти открытого виджета, не в localStorage и не в новой серверной таблице.

Можно изменить несколько полей нескольких строк. Enter применяет обычный input в буфер; для многострочного ввода используйте кнопку «Применить». Escape закрывает текущий редактор без применения. Общая кнопка сохранения и Ctrl+S отправляют один `/table-changes`. Повторное редактирование видит ранее набранную правку. Возврат значения к исходному удаляет эту правку из буфера. Переход к другой странице таблицы не удаляет правки; число правок вне страницы показано. Переключение на дерево не уничтожает смонтированную таблицу.

Перед записью **все** строки проверяются на область доступа, ревизию записи, ревизию конфигурации, разрешённые поля, типы и поддержанные action handlers. Затем выполняется исходный **EditMultipleCmd** с адаптированным транспортом NativeEditCmd, внутри существующей общей `Command`-транзакции. Сохранён его исходный цикл по записям и **событие `update_multi|<search_type>`**. Несколько независимых immediate PATCH не заменяют эту операцию.

Исходный `EditMultipleCmd` получил только фабрику класса дочернего EditCmd; старый путь по умолчанию продолжает создавать исходный класс. Native-путь предоставляет валидированные значения исходным action handlers и сохраняет оригинальные pre/post actions, defaults, commits и triggers. Не добавлен универсальный endpoint для произвольных Python-команд.

На настоящем сервере проверены **две строки / три ячейки / одна команда / одно update_multi**. Отдельно проверена ошибка оригинального NonEmptyAction во второй строке: первая запись откатывается, событие update_multi не публикуется. Конфликт ревизий или ошибка действия не удаляет набранный текст; пользователь может исправить значение либо отменить свои правки. Принудительного «сохранить поверх чужого» нет.

Пределы: **100 строк и 1000 изменённых ячеек в пакете**. Новые записи пока создаются через штатный popup Insert/EditWdg; они не включены в тот же inline-буфер как виртуальные строки. Полные Fill/Paste/Save All для произвольных custom widgets, работа с sequence/revision и комплексными WorkHours/Gantt actions этим пакетом не эмулируются. Специальные панели продолжают сохранять через собственные операции.

Сервер не пропускает неизвестные `save_cmd`, `save_class_name`, `extra_action`, `extra_data`, parent/connect hooks: требует отдельный адаптер. Межпроцессная сериализация с legacy-клиентами и exactly-once-повтор после потери HTTP-ответа не гарантируются; автоматического retry записи нет. Откат DB-транзакции не способен отменить произвольные внешние файловые/сетевые эффекты пользовательских триггеров.

## 4. Настоящий NULL и точность чисел

Проверка на оригинальном SObject обнаружила ошибку прежнего native-пути: явный `None` отклонялся, а базовый serializer мог превращать NULL в `''` или `0`. Добавлен **опциональный** `SObject.set_value(..., allow_none=True)` для явного native NULL; старое поведение всех вызовов без этого флага сохранено. Проверки прав поля, prevalidation, запрет NOT NULL и update tracking остаются исходными. Nullable boolean с NULL не превращается в false.

Для значений редактора и ревизии NULL теперь сохраняется как JSON null; display-форматирование по-прежнему получает ожидаемое legacy-значение. Проверен полный круг UI → original command → SQLite → повторное чтение. На больших целых и decimal-сравнениях буфера не используется округление JavaScript Number: разные значащие цифры после 53 бит не исчезают как «одинаковое значение». Это не обещание произвольной decimal-арифметики браузера.

## 5. Preview обычной таблицы

Явный `ThumbWdg` теперь отображает зарегистрированный файл из настоящего snapshot. Пакетный выбор повторяет порядок `ThumbWdg.preprocess`: icon context → publish context → publish process → оставшийся latest, с сохранением более раннего найденного результата. Учитываются `icon_context`, `latest_icon`, `cascade_search` и поддержанные параметры размера/ссылки.

Файлы читаются из snapshot XML и оригинальных File, проходят проверку принадлежности и пути. Браузер получает защищённый URL существующего файлового endpoint, **без физического пути или ticket в URL**. Если изображения нет, виден отдельный пустой preview. В тесте реальный PNG был опубликован оригинальным simple_checkin; браузер получил его через исходную файловую регистрацию.

Это **базовая поддержка зарегистрированных icon/web/main изображений**, не перенос всех ветвей ThumbWdg. Генерация thumbnail, redirect/ref expression, пользовательские script callbacks, file://, versionless и sequence требуют дополнительных адаптеров; соответствующие варианты не считаются готовыми. SVG/HTML не исполняются как preview. По умолчанию открывается native карточка записи; detail=false использует защищённую ссылку файла, detail=none не открывает карточку.

## 6. Геометрия и новая стилистика

Колонки: изменение ширины мышью и клавиатурой на разделителе, перестановка заголовков, закрепление слева, скрытие/возврат и сброс. Начальные поля, подписи и геометрия приходят из widget_config. **Локальные геометрические предпочтения** сохраняются отдельно для проекта/target в браузере; этот этап не записывает их в серверный WidgetSettings или widget_config. «Настроить представление» по-прежнему открывает настоящий конфигурационный редактор.

Три плотности, перенос текста, активная ячейка, стрелки/Home/End, F2/Enter, Shift-выделение диапазона, контекстное меню мышью или Shift+F10. Выделение строк и редактирование значений разделены. Клик по кнопке вложенного виджета остаётся её действием, а не превращается в текстовый редактор.

Обновлены общие цветовые токены, светлая/тёмная темы, sidebar, вкладки, таблицы, формы, меню, диалоги и панели. Используются системные шрифты без CDN и без файлов шрифтов. Цвета статусов задаёт исходный pipeline. Функциональные пункты админки не заменены дизайнерским hard-coded меню. Изменение темы не меняет palette/настройки проекта в БД.

## 7. Фактические проверки этого архива

| Проверка | Результат |
|---|---:|
| Python unit | 953 |
| JS тесты настоящих методов буфера | 15 |
| Прежняя synthetic HTTP-регрессия | 322 |
| Новый оригинальный сервер/SQLite, HTTP | 37 |
| Новый оригинальный сервер/SQLite, browser | 36 |
| Повтор оригинальных Global/form/pipeline/schema flows, HTTP | 83 |
| Повтор оригинальных Global/form/pipeline/schema flows, browser | 42 |
| XML parity | 80 файлов, 487 views, 11 370 сравнений; ноль расхождений в проверенной области |
| Vue build | 38 SFC, Vue 3.5.13, готовый JS/CSS |

Итого **120 HTTP и 78 browser-сценариев через original backend**; 322 synthetic HTTP указаны отдельно, не выдаются за сквозной сервер. Старые 212 synthetic browser-сценариев целиком заново не выполнялись: их прежнее ожидание немедленного inline-save не соответствует новому целевому поведению. Новый код проверен оригинальными сценариями и отдельными тестами буфера.

Original runner использует полные временные копии штатных SQLite seed, реальные FirstRunInit/CherryPy, пароль/ticket, Search/SObject, EditCmd/EditMultipleCmd, triggers и persistence. Проверка подписи лицензии **изолирована явным --isolate-license только в тестовом процессе**; production-проверка не отключена. Подлинность лицензии этим тестом не подтверждается.

Перед браузерным тестом предпринята прямая навигация: среда возвращает ERR_BLOCKED_BY_ADMINISTRATOR. Поэтому далее явно включён HTTP-мост; для защищённых img в новом наборе также использован тестовый маршрут доставки через тот же настоящий HTTP endpoint. Это **не доказательство нативных cookies/CSP/navigation/WebCrypto**. Серверные session/CSRF/Origin отдельно проверены настоящими запросами. Скриншоты помечены ORIGINAL TACTIC / SQLITE TEST DATA / isolated signature / HTTP bridge. Пользовательские рабочие БД не читались и не упаковывались.

Windows BAT/PowerShell, PostgreSQL/MySQL, внешние плагины и полный набор реальных пользовательских конфигураций в этом этапе не проверены. Внешние testdeps (cgi.py) не включены в поставку. Все результаты, завершённые текущие логи и исходные тесты находятся в `docs/native-ui/0.12/validation` и `tests/native_ui`. Прерванные суммарные shell-прогоны не выдаются за полные: девять отдельных synthetic HTTP-наборов завершены и объединены по их фактическим JSON.

Повторение в developer-окружении:

```bat
python -W ignore -m unittest discover -s tests/native_ui -v
node tests/native_ui/test_grid_state_012.cjs
node tools/native_ui/build.cjs
python tests/native_ui/run_original_012.py --output D:\TEMP\tactic012-new --chromium C:\path\chrome.exe
python tests/native_ui/run_original_regression_012.py --output D:\TEMP\tactic012-regression --chromium C:\path\chrome.exe
```

Два original runner создают свои временные установки, не принимают путь к рабочей базе. `--isolate-license` только для изолированного CI без криптографических зависимостей. `--bridge` — только при реальном запрете навигации. Для тестов браузера требуется developer Playwright/Chromium; обычному пользователю не нужен.

## 8. Состав, исходники и границы

`SOURCE_MAP_012.md` показывает соответствие исходным классам; `changes-from-0.11.patch` / JSON — фактический diff к архиву с именем 1.1. Внутренний манифест и внешний Verification фиксируют хеши, номер версии и результаты.

Поставка не содержит .runtime, пользовательские пароли/БД, временные тестовые базы и payload, bytecode, .git и font-файлы. Оригинальные штатные seed сохранены побайтно. Предыдущие документы остаются историческими отчётами своих версий. Sidebar и backend остаются TACTIC; **полного удаления legacy UI, полной поддержки обычных ролей, multisite/multiworker и всех specialised views пока нет**.
