# TACTIC 5.0 — Vue Source Fork 0.20

Полное дерево исходников на основе выпущенной **0.19**. Этот этап сокращает **12 BAT-файлов до трёх**, не убирая операции и защитные подтверждения. Ядро остаётся `5.0.0.a02`; Vue в комплекте — прежний `3.5.13`. Готовая браузерная сборка включена.

## 1. Три файла в корне

| Файл | Двойной щелчок / назначение |
|---|---|
| **START_TACTIC.bat** | Запускает сервер по сохранённым параметрам. Без настройки — кластер из трёх TACTIC-процессов на localhost:9123. |
| **SETUP_ENV.bat** | Устанавливает локальные Python и зависимости. Работает до установки Python; не создаёт и не обновляет БД. |
| **MANAGE_TACTIC.bat** | Открывает меню параметров запуска, диагностики, разрешений, обслуживания SQLite и сборки Vue. Само открытие меню ничего не запускает и не меняет. |

**В корне и во всём дереве ровно три `.bat`**, не ещё десяток спрятанных старых BAT. Все действия вызывают прежние Python/PowerShell-инструменты внутри `tools/local`. Старые раздельные BAT удалены из новой поставки, их функциональность не удалена.

Важно: **START_TACTIC по умолчанию теперь запускает три процесса**, как прежний START_CLUSTER. Для одного процесса используйте `--single` или сохраните режим `single`; для legacy — `--legacy`.

## 2. Обновление уже работающей установки

**Не удаляйте local_data. Не выполняйте INIT, SETUP или UPGRADE повторно ради 0.20.** Остановите всю прежнюю группу, сохраните резервную копию данных и распакуйте 0.20 отдельно. Не накладывайте архив поверх старой папки: распаковка не удалит старые BAT.

Из НОВОГО каталога `TACTIC-5.0`, подставив свои рабочие пути:

```bat
set "TACTIC_PYTHON=D:\TACTIC_OLD\TACTIC-5.0\.runtime\python\python.exe"
START_TACTIC.bat --data-dir "D:\TACTIC_OLD\TACTIC-5.0\local_data" --port 9123 --workers 3
```

Адрес: `http://127.0.0.1:9123/tactic/admin/`. При внешней конфигурации сохраните свой `--config "...\tactic-conf.xml"`. Данные и Python могут быть в разных старых папках. Остановка всей группы — Ctrl+C в окне запуска. Шлюз и все workers остаются на localhost; схема балансировки не менялась.

Прочие режимы:

```bat
START_TACTIC.bat --single --data-dir "D:\TACTIC_DATA"
START_TACTIC.bat --legacy --data-dir "D:\TACTIC_DATA"
START_TACTIC.bat --mode cluster --port 9123 --workers 3 --worker-base-port 9200
```

Для `--single`/`--legacy` не передавайте `--workers`, `--worker-base-port` и `--timeout`: они относятся только к группе и не будут молча проигнорированы. Диапазон workers — 2–8. Внешний порт — 1024–65535. Порты проверяются на пересечение; отсутствие свободного порта обрабатывает прежний cluster launcher.

## 3. Один раз указать пути, затем запускать двойным щелчком

Откройте **MANAGE_TACTIC.bat → 1. Параметры запуска**. Укажите Python, каталог данных, внешний XML (при необходимости), порт, число workers и режим `cluster/single/legacy`. Сохранение требует подтверждения. Затем для ежедневного запуска достаточно START_TACTIC.

Если рядом ещё нет Python, меню предложит указать существующий `python.exe` или отдельно установить окружение. Неверный явно переданный `--python` не заменяется незаметно случайным Python из PATH.

То же без меню:

```bat
MANAGE_TACTIC.bat settings --python "D:\OLD\.runtime\python\python.exe" --data-dir "D:\OLD\local_data" --mode cluster --workers 3 --port 9123 --save
START_TACTIC.bat
```

Параметры сохраняются в **launcher.local.json рядом с тремя BAT**. Он содержит только пути/режим/порт, не пароли, не TACTIC tickets и не настройки widget_config. При следующем обновлении можно перенести этот один файл в новое дерево. В поставку он не включён, чтобы не навязывать чужие пути. Предыдущая версия файла сохраняется как `.previous`; повреждённый JSON и конфликт записи не перезаписываются молча.

Приоритет Python: `--python` → `TACTIC_PYTHON` → сохранённый профиль → локальная `.runtime`. Приоритет параметров запуска: явные аргументы → профиль → значения по умолчанию. Относительные пути считаются от нового каталога исходников, а не от случайной текущей папки.

Явный новый `--data-dir` без `--config` не наследует старый внешний XML другого каталога. `--config` без `--data-dir` выводит каталог данных только из стандартного расположения `<data>/config/...xml`; для другого расположения укажите оба пути. Никакого поиска «похожей базы» в Downloads нет.

## 4. Меню обслуживания

В MANAGE пять групп:

1. Параметры запуска.
2. Диагностика: окружение, структура managed SQLite, создание/регистрация сервера.
3. Разрешения: просмотр, только чтение, запись, файлы, запуск сохранённых Python-скриптов, отдельное отключение uploads/scripts.
4. База: новая SQLite, обновление с backup, восстановление прерванной установки.
5. Пересборка готового Vue для разработчика.

Кнопки INIT/UPGRADE не запускаются автоматически при диагностике. После завершения операции и ENTER меню возвращается. В обычном запуске START нет лишних шагов меню.

| Раньше | Теперь |
|---|---|
| START_CLUSTER.bat | START_TACTIC.bat |
| START_TACTIC.bat (один процесс) | START_TACTIC.bat --single |
| START_LEGACY.bat | START_TACTIC.bat --legacy |
| SETUP_ENV.bat | SETUP_ENV.bat |
| CHECK_ENV.bat | MANAGE_TACTIC.bat check env |
| CHECK_LOCAL_DB.bat | MANAGE_TACTIC.bat check db |
| CHECK_STARTUP.bat | MANAGE_TACTIC.bat check startup |
| CONFIGURE_NATIVE.bat | MANAGE_TACTIC.bat configure |
| INIT_LOCAL_SQLITE.bat | MANAGE_TACTIC.bat db init |
| UPGRADE_LOCAL_SQLITE.bat | MANAGE_TACTIC.bat db upgrade |
| RESTORE_LOCAL_SQLITE.bat | MANAGE_TACTIC.bat db restore |
| BUILD_VUE.bat | MANAGE_TACTIC.bat build |

Прямые примеры:

```bat
MANAGE_TACTIC.bat check db --data-dir "D:\TACTIC_DATA"
MANAGE_TACTIC.bat configure --data-dir "D:\TACTIC_DATA" --writes on
MANAGE_TACTIC.bat db upgrade --data-dir "D:\TACTIC_DATA"
START_TACTIC.bat --dry-run
```

`--dry-run` показывает точную команду без выполнения, создания БД или сохранения параметров. Для прямых команд сохраняется код возврата дочернего инструмента, в том числе **3 у check db**, когда структура не готова. Этот статус не запускает миграцию. `check startup` выполняет оригинальную инициализацию, которая может писать в БД — это НЕ read-only диагностика; остановите сервер.

**CREATE, ввод пароля, UPGRADE, RESTORE, ENABLE/DISABLE и существующие lock/backup не удалены.** `db restore` только восстанавливает прерванную установку, не откатывает уже изменённую работающую БД. `db` принимает только управляемую SQLite без внешнего --config, а не произвольную PostgreSQL/MySQL-инсталляцию. Новая оболочка не подавляет ошибки, не включает запись сама и не заменяет работу исходных инструментов.

## 5. Окружение и первый запуск с нуля

```bat
SETUP_ENV.bat
SETUP_ENV.bat --offline
SETUP_ENV.bat --repair
```

Загрузка идёт через прежний `setup_env.ps1`, manifest и проверки SHA-256/подписи/zipapp. URL, версии и зависимости **не менялись, загрузки заново не проверялись**. Ремонт выполняется отдельным PowerShell-процессом, без запущенного в этом меню Python, который требовалось бы перемещать. Перед ремонтом всё равно остановите серверы, использующие данное окружение. `--repair` не гарантирует работу при стороннем процессе, удерживающем файлы.

Сохраняются также прежние формы параметров `-Repair` и `-Offline`. Нет автоматического запуска INIT/UPGRADE после SETUP. Для совершенно нового пустого каталога используйте MANAGE → База → Новая SQLite, затем отдельный UPGRADE и check db. **Это не инструкция инициализировать существующий local_data заново.** PostgreSQL-сервер по-прежнему не устанавливается.

## 6. Технические детали

BAT — тонкие ASCII/CRLF-входы с отключённым delayed expansion. Они вызывают общий `tools/local/tactic_bootstrap.ps1`, который до Python обрабатывает SETUP, выбор интерпретатора и справку. Затем `control.py` (только стандартная библиотека) делегирует действие прежним `launch.py`, `cluster.py`, `configure_native.py`, `setup_env.ps1` или `build.cjs`.

Аргументы PowerShell→Python передаются JSON-конвертом через окружение, не исполняемым `-Command` или повторным `CALL`. Дочерние инструменты запускаются списком argv, без shell=True и без перехвата stdout/stdin: приглашения подтверждения, пароль и START/RUNNING/END остаются в консоли. Ctrl+C передаётся оригинальному launcher, контроллер ждёт завершения дочерней очистки и не повторяет команду.

Дополнительный JSON-профиль нужен **только для локального запуска до открытия БД**. Настройки интерфейса/таблиц/поиска остаются в оригинальном WidgetSettings/widget_config. Нативная авторизация, роли, защита CSRF, бизнес-команды, логика миграций и структура seed в этом этапе не менялись. Обновлены лишь пользовательские подсказки, чтобы не ссылаться на удалённые BAT.

## 7. Проверки и ограничения

Фактические текущие результаты: `docs/native-ui/0.20/validation/summary.json` и внешний Verification.

Итог: **1304 Python unit-теста** (из них 77 контроллера/entry contracts), **177 JavaScript-проверок**, **25 subprocess-проверок контроллера**, **352 HTTP-сценария** через оригинальную группу и **63 проверки управления этой группой (включая коды завершения дочерних наборов; повторно к HTTP не суммируются)**. 50 Vue SFC собраны и сверены по хешам. XML parity — 80 файлов, 487 views, 11 370 сравнений без расхождений в проверенной области.
 Включены отдельные тесты трёх entry points, диспетчеризации, сохранения профиля, конфликтов, специальных символов в argv, кодов возврата, Ctrl+C и отсутствия автоматических подтверждений.

Portable subprocess-набор сравнивает вызов оригинального read-only check db напрямую и через контроллер на временном полном seed; побайтно проверяет неизменность БД/конфигов. **Это исполнение Python-контроллера на Linux, а не Windows BAT.** Сквозная HTTP-регрессия использует оригинальный кластер TACTIC и временные SQLite, с явной изоляцией подписи тестовой лицензии. Подпись в рабочем коде не выключена.

**Windows BAT/PowerShell 5.1 и фактическая загрузка окружения здесь не исполнялись.** Включён отдельный smoke-test `tests/native_ui/test_bootstrap_020.ps1` для Windows; его наличие не считается прохождением. PostgreSQL/MySQL, все действия UI в браузере и сетевые файловые системы заново не проверены. JavaScript/готовая сборка и серверная HTTP-регрессия проверены отдельно; новые браузерные цифры этого релиза не заявляются.

## 8. Состав и откат

Полный форк с готовыми JS/CSS, три BAT, shared helpers, тесты, source map и patch к .19. Поставка исключает `.runtime`, пользовательские БД/пароли/профили, private test установки, сырые worker-журналы, caches/pyc/.git и файлы шрифтов. Штатные исходные seed сохранены. Исторические отчёты остаются отчётами своих версий.

Старые документы в `docs/native-ui/0.x` содержат прежние имена BAT — используйте таблицу соответствия выше. Никаких старых BAT с автоматическими переадресациями не добавлялось. При возврате на 0.19 снова используются её прежние BAT. START_TACTIC --legacy меняет только рендерер, не откатывает данные; старые UI-каталоги всё ещё нужны.

Справка по реализации командных границ: Microsoft about_PowerShell_exe (Windows PowerShell 5.1), раздел -File; Python subprocess, раздел Security Considerations. Переменные оболочки могут быть раскрыты вызывающей CMD/PowerShell ещё до входа в BAT; не передавайте произвольную командную строку как путь к интерпретатору.
