# Первое задание для продолжения

Ниже текст, который можно дать новой сессии разработки после предоставления полного source fork 0.20 и этого handoff. Он относится к проекту, а не к устройству или возможностям сервиса Codex.

---

Продолжаем существующий форк TACTIC 5.0 с нативным Vue UI. Основа — `NATIVE_UI_VERSION=0.20`, ядро `5.0.0.a02`. Прочитай `docs/handoff-0.20/00_START_HERE.md`, архитектуру, матрицу parity и план. Проверяй сведения по фактическим исходникам.

Главная цель — функциональное соответствие оригинальному TACTIC, а не создание нового похожего CRUD-приложения. Sidebar, admin, table/edit/tab/layout должны происходить из исходных widget_config и их rules. Запись идёт через исходные команды/actions/transactions/triggers.

На первой итерации:

1. Проверь baseline, структуру и имеющиеся незакоммиченные изменения. Не удаляй local_data, не выполняй INIT/UPGRADE без отдельного задания, не трогай рабочую БД. Создай baseline commit и отдельную ветку; секреты и runtime не добавляй в Git.
2. Повтори доступные unit/JS/build/metadata проверки из handoff. Недоступные зависимости и непроверенные среды отрази явно; не отключай авторизацию или лицензию в production ради прохождения теста. Тестовая signature isolation не является способом рабочего запуска.
3. На отдельной тестовой установке открой три представления: Global Users, Groups с вложенным Access Rules, и один пользовательский SearchType с обычным текстом, статусом/исполнителем, thumbnail и хотя бы одним edit_item override. Сравни native и legacy на одной конфигурации и одинаковых данных.
4. Запиши различия по каждому: источник слоёв, структура таблицы, содержимое ячеек, click/right-click/double-click, редактор, defaults/actions, Save Changes, validation/rollback, persistence, permissions. Отличай баг от намеренно неподдержанного handler.
5. Выбери **один конкретный фундаментальный дефект** из этих наблюдений, перенеси соответствующий алгоритм и добавь regression test. До исправления тест должен воспроизводить несовпадение; после исправления проверить root/nested/restored вариант. Не начинать одновременно миграцию ORM, build-tooling и всех экранов.
6. Сохрани промежуточные исходники commit/checkpoint до длинных тестов. Заверши проверяемым diff, actual командами тестов, ограничениями и обновлением матрицы. Если выдаёшь архив — только полный форк с собранным Vue, CRC/SHA/manifest и без secrets/runtime/fonts.

Особые требования:

- Не возвращать большие повторные headers; дополнительные действия таблиц держать в меню. В корне остаётся ровно три BAT.
- `values`, display `cells` и draft — разные данные. CellEdit использует edit/edit_item, полная EditWdg — свой lookup. Apply в ячейке не пишет в БД; один Save Changes сохраняет пакет через EditMultipleCmd и update_multi.
- Не заменять неизвестный специализированный UI generic-таблицей. Регистрировать и проверять renderer в основной и вложенной точках.
- Пользовательские XML, comments/CDATA/unknown атрибуты сохранять при целевой правке. Не пересобирать весь документ из неполной проекции.
- Не доверять title или query params как разрешению на class/SQL/command execution. Проверять target/project/site/user на сервере.
- При потере ответа от write не повторять автоматически. Один writer lane не гарантирует exactly-once или rollback внешних эффектов.
- Не объявлять весь класс перенесённым по одному screenshot/alias. Статические `UNREVIEWED` обновлять только с конкретными evidence.

В финальном отчёте: изменённые файлы, исходные legacy-методы, что стало совпадать, что осталось отличаться, actual tests/команды/платформа, и безопасная инструкция обновления без переинициализации данных.
