# Самостоятельный серверный комплект PostgreSQL / Apache

Комплект содержит версионированные Linux-образы TACTIC Stream, Apache/Webmin
и PostgreSQL 18.6, Compose, управление, лицензии и контрольные суммы SHA-256.
Сервер использует установленный Python-пакет и собранный Vue. Исходники,
Node.js и Python-зависимости приложения на хосте не нужны. На хосте требуются
Docker Compose и Python 3.10+. Архитектура образов соответствует машине сборки.

## Сборка из исходников

Из каталога `tactic_stream` при запущенном Docker:

```powershell
.venv/Scripts/python.exe -B -m tools.server_delivery --output ../releases/server-0.112.192
```

Каталог назначения не должен существовать. Все три образа входят в `images.tar`.
Сохранённые пароли, тикеты, БД, repository и том зависимостей разработчика не
копируются. `manifest.json` содержит версию, идентификаторы образов и контрольные
суммы. Успешная сборка сама по себе не означает производственную приёмку.

## Новая установка

Перенесите весь комплект на целевую машину и выполните из его каталога:

```sh
python manage.py load
python manage.py init
python manage.py check
```

`load` проверяет контрольные суммы всех файлов перед загрузкой образов.
`init` создаёт отдельные секреты PostgreSQL и Webmin в `.local`, дожидается
PostgreSQL, готовит новый конфиг и дважды запрашивает пароль администратора
TACTIC штатной CLI-командой. Пароля по умолчанию нет. Существующие SQLite-данные
и конфигурация не преобразуются. PostgreSQL-конфиг сохраняется; штатная
инициализация откажется заменять уже созданную БД.

Проект Compose по умолчанию — `tactic-stream-server`. Для отдельного экземпляра
используйте отдельный каталог комплекта со своими секретами, одинаковый
`--project-name ИМЯ` во всех командах и свободные `STREAM_HTTP_PORT` /
`STREAM_WEBMIN_PORT`. Переменные портов задаются перед запуском.

- Приложение: `http://127.0.0.1:8082/`.
- Webmin: `https://127.0.0.1:10000/`, пользователь `root`, пароль в `.local/webmin-password`.
- Порты PostgreSQL и backend наружу не публикуются.
- Данные, repository, конфиг и журналы находятся в томе `stream_data`;
  PostgreSQL, конфигурация Apache и Webmin имеют отдельные тома.

Команды `status`, `logs`, `up`, `stop` выполняются через `manage.py`.
Остановка сохраняет тома. Храните `.local` в защищённых резервных копиях:
секреты необходимы для доступа к существующим данным. При наличии тома
утраченный секрет не генерируется заново. `check` проверяет сертификат Webmin,
вход/выход, маршруты Apache, ресурсы интерфейса, воркеры и транзакции PostgreSQL.

На Linux управление закрывает доступ к `.local` для других пользователей (0700),
а файлы секретов делает читаемыми для приложения без root внутри контейнера (0644).
Защиту на хосте обеспечивает закрытый родительский каталог; сохраняйте её при
копировании секретов. Файловые secrets Compose сохраняют права файла хоста;
см. [контракт Docker](https://docs.docker.com/reference/compose-file/services/#secrets).

## Обновление установленного комплекта

Сначала сохраните резервную копию БД, repository, конфигурации и секретов `.local`.
Оставьте предыдущий комплект. Новый распакуйте отдельно, безопасно скопируйте
туда существующий `.local`, сохраните прежнее имя проекта Compose и настройки
портов. Выполните `load`, `update`, `check` из нового каталога.
`update` останавливает backend, запускает штатное обновление схем и пересоздаёт
сервисы из загруженных образов с прежними томами. При ошибке миграции backend
остаётся остановленным. Если схема необратимо изменилась, для возврата нужна
резервная копия БД; запуск прежнего образа не откатывает схему.

Этот комплект предназначен для новой установки PostgreSQL и штатных обновлений.
Перенос legacy-проектов и полная проверка GUI остаются условиями L12. Отдельный Windows-
комплект прошёл проверку установки/запуска на свежей Windows 11 build 26300.
Переход 0.112.192 → 0.112.193, восстановление холодных копий и откат в независимых
томах PostgreSQL прошли проверку; см. [порядок восстановления и приёмку](RECOVERY_ACCEPTANCE.md).
Замена значения vendor в конфиге
не переносит SQLite-данные. Для внешнего доступа требуется настроить TLS и
доверенные proxy headers под целевое окружение.
