# Настройки проектов

> Выберите карточку в каталоге, затем явно активируйте проект. Сам выбор карточки рабочее пространство не переключает.

Деактивация оставляет приложение без активного проекта. Активация восстанавливает его сохранённые вкладки/леяут и записывает обычный URL проекта. Конфигурация остаётся открытой. Эти действия выполняются сразу; «Сбросить» не отменяет переключение проекта.

Администратор создаёт проект через существующий ProjectCreation и штатные CreateProjectCmd/импорт шаблона. Редактирование использует штатные метаданные `sthpw/project` и общий RecordForm. Встроенные admin/system не редактируются и не экспортируются здесь. Создание и правки записи сохраняются собственными контролами, независимо от общего черновика Configuration.

Экспорт шаблона вызывает административную ProjectTemplateExportCmd, делегирующую штатной ProjectTemplateCreatorCmd и FileUndo. ZIP копируется в существующий кэш ассетов с тикетом для скачивания. Это экспорт шаблона, не удаление проекта или данных. Ошибка активации после создания остаётся в мастере: активацию можно повторить без повторного создания проекта.

Владельцы: ProjectSettings/ProjectChooser/ProjectCreation/RecordForm, штатные CreateProjectCmd, ProjectTemplateCreatorCmd, EditCmd и каталог проектов. Приватные проверки подтверждают настоящий manifest ZIP и запрет экспорта для пользователя без административных прав.

Слева находится дерево depot, справа, в основной рабочей области — чейнджлисты с номерами и раскрываемыми файлами. Стрелка раскрывает depot, stream, папку или чейнджлист. Дочерние узлы загружаются страницами; «Загрузить ещё» продолжает только выбранную ветку. Выбор папки переключает рабочую область на файлы depot; «Файлы чейнджлиста» возвращает чейнджлисты. Каждый чейнджлист показывает номер в проекте, описание, владельца и состояние; его файлы можно выделять для команд. Перенос файлов и unshelve принимают номер чейнджлиста проекта, например #42. При выборе чейнджлиста фильтр папки depot сбрасывается. «Обновить» загружает текущую опубликованную версию.

В файловых проектах доступны обычные вкладки поиска объектов Search. Служебные файловые таблицы читаются через штатный файловый API; администратор может просматривать их схему и число записей в Search Types. Интерфейс Perforce-like открывается в доке Commit Queue. Его можно объединять в стек с Search, перемещать или выносить штатными средствами докинга. «Развернуть панель» занимает всю рабочую область; восстановление возвращает раскладку без перезаписи сохранённых пропорций. Восстановленный из кэша проект выбирает файловый интерфейс до обновления с сервера.


Слева находятся независимые деревья Depot/Workspace, справа — настраиваемые рабочие вкладки. Меню «Вид» открывает или восстанавливает Files, Pending, Submitted, History, Shelved, Reverted, Conflicts и Transfers. Вкладки имеют пиктограммы, закрываются, переименовываются и перемещаются; состав сохраняется для пользователя и проекта. «Новая вкладка» и «Настроить вкладку» задают источник и фильтр путей. Files по умолчанию следует выбранному дереву; фиксированные источники сохраняют собственный фильтр. Выбор папки не заменяет чейнджлисты. Pending включает shelves. Копирование номера чейнджлиста даёт #номер внутри проекта для штатных unshelve/move. Workspace в ТС показывает индексированный серверный Have; проверка локального диска выполняется в ТХ. Редакторы открываются из меню операций.

Вкладки Search администратора читают служебные файловые таблицы через штатный файловый API. Сервер выбирает команду чтения по зарегистрированным метаданным Search Type при каждом запросе; старый кэш метаданных клиента не направляет поиск в обычный Search. Фильтры колонок, ограниченные страницы и счётчики сохраняются. Неадминистраторам эти служебные таблицы по-прежнему недоступны. ТХ повторяет запрос только при неподдерживаемом дополнительном аргументе, а не при отказе в доступе с упоминанием progress в traceback.

## Редактор проекта

«Редактировать выбранный проект» открывает модальный редактор: неизменяемый код, название, категория, тип, описание, признаки архива/шаблона и изображение. При закрытии изменённой формы можно продолжить редактирование или отменить правки. Сохранение использует штатную команду и владельца изображения. В Stream сохраняются дополнительные поля status/palette; неподдержанные пользовательские inputs явно блокируют Save. Архивация использует штатный retire с историей, а не прямую запись статуса. Активация остаётся отдельной немедленной операцией рабочего пространства.
