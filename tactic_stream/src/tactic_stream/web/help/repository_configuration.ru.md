# Настройки репозиториев

> Сводка показывает фактические алиасы, разрешённые штатными Config/Environment. «Открыть редактор репозиториев» открывает выбранный алиас в структуре `RepositoryEditorView.qml`.

В редакторе есть каталог, имя, серверный путь, клиентские пути Windows/Linux, цвет, доступность и расширенные настройки. Имена/цвета и клиентские пути меняют тот же черновик File repository, что и расширенные XML-поля: второго хранилища репозиториев нет. Пустые клиентские пути используют штатный корень сервера. В расширенных настройках сохранены ширина номера версии, checksums, versionless copy/symlink/hardlink, URL, sandbox/local/handoff-пути и их исходная валидация.

«Включён» и «По умолчанию» задают доступные репозитории и начальное место назначения новых чекинов браузера; они хранятся в browser preferences. «Добавить репозиторий» регистрирует алиас в штатной карте `checkin/asset_base_dir`. Имя, цвет, клиентские пути и URL меняют тот же черновик Config. Ревизия сохраняет свой прежний репозиторий. SDK без явного алиаса использует прежний Naming: настройка браузера не перенаправляет всех клиентов сервера.

Серверный корень редактируется. Перед его сменой остановите чекины и скопируйте все файлы в существующую новую папку сервера. Сохранение проверяет штатные пути `sthpw/file` и SHA-256 существующих исходных файлов относительно новой папки. Отсутствующие или изменённые файлы, выход за пределы корня и удаление используемых алиасов отклоняются. Сохранение само не переносит и не удаляет файлы. После изменения корней/URL перезапустите backend, чтобы обновились HTTP-маршруты. Это проверка подготовленной смены папки, а не перенос при параллельных чекинах. Легаси `base_dir_alias` сохранён со штатной семантикой Environment; новые алиасы добавляются в `asset_base_dir`, чтобы не подменять web URL. Клиентские пути Windows/Linux передаются через `get_base_dirs`/`get_client_dir`; браузер другую машину не проверяет.

«Проверить пути» вызывает команду администратора `tactic.ui.app.RepositoryPathsCmd`. Проверяются текущие пути редактора, включая ещё не сохранённый репозиторий: создание папки через FileUndo и временная проба чтения/записи. Пустые и неверные пути отклоняются либо отмечаются недоступными; пробы удаляются. Открытие страницы не создаёт папок. Проверка не переносит и не заменяет файлы.

Apply Configuration сохраняет эту страницу, Reset восстанавливает её, не затрагивая остальные. В Repository Editor Cancel восстанавливает страницу репозиториев, Save применяет её; обе кнопки оставляют редактор открытым. Close сохраняет pending edits, Cancel Configuration предлагает сохранить или отменить. Окно использует общие перемещение и разворачивание.

Владельцы: `RepositorySettings.vue`, `RepositoryEditor.vue`, общий черновик `ServerConfiguration.vue`, `RepositoryPathsCmd`, штатные Config/Environment/FileUndo. Repository Sync, watch-folder mappings и S3 исключены.
