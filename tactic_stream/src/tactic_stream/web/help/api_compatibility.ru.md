# Совместимость ядра и API

> Каталог содержит 129 исходных exposed методов TACTIC. В 0.112.40 доступны 127 входных точек, две исключены. Доступность и совпадение сигнатуры не означают полной совместимости всех аргументов и побочных эффектов. `full_api_parity_verified` остаётся `false`.

## Где смотреть конкретный метод

Откройте справочник API: там исходная сигнатура, docstring, пояснения EN/RU, параметры и запуск через JSON. Python-пример использует исходный XML-RPC SDK. `/api/documentation` возвращает тот же каталог, `/api/compatibility` — перечень методов, исходных вызовов ТХ и ограничения. JSON и XML-RPC используют одно ядро; их форматы ответа могут отличаться.

Например, исходный XML-RPC `query` возвращает Python literal строку. `TacticServerStub.query` разбирает её в список словарей; JSON и local SDK возвращают список напрямую. При использовании `xmlrpc.client.ServerProxy` учитывайте исходное представление, не считайте длину строки количеством объектов.

Сервер не импортирует каталог `legacy` или ТХ. Родные `pyasm`/`tactic` классы перенесены в пакет. Исходники ТХ и TACTIC используются только для сверки и изолированных тестов.

## Что проходит штатным путём

| Область | Механизм | Существенная граница |
| --- | --- | --- |
| Авторизация и чтение | Ticket, Security, Search, SearchKey, Select, Schema | Проект, тип, поле и родитель проверяются в ядре; прямой SQL не является обходом политики |
| Объекты | insert/update/batch, get_unique_sobject, clone, retire/reactivate, delete | Запись через Command/SObject; системные редакторы требуют администратора |
| Связи | родитель, instance, connection, hierarchy, dependencies | Направление, проект, тип ссылки и права проверяются; неперенесённый вариант возвращает ошибку |
| Задачи и заметки | Task, Pipeline, Workflow, Note, Discussion | Права родителя/автора, статусы, журналы и триггеры сохраняются |
| Файлы | Snapshot, FileCheckin, FileAppendCheckin, FileGroup, FileUndo | Ticket uploads, версии/revision/versionless, locks, naming, metadata и откат; Repository Sync и S3 исключены |
| Серверные скрипты | PythonCmd, local TacticServerStub, родные импорты | Python требует администратора либо явного `api_cmd` разрешения и доступа к проекту |
| Настройки и администрирование | XML configs, SearchType/schema, widget definitions, users/groups, plugin installation | Browser UI не выдаёт DTO за исходный HTML виджет |
| Отмена | Command, Transaction, SObjectUndo, FileUndo | SQL, запись журнала, триггеры и файлы должны завершиться согласованно |

`missing_method(func, args)` воспроизводит исходный диагностический результат `False`. Это не успешное выполнение неизвестной операции. Вызов отсутствующего RPC-метода по его имени продолжает возвращать Fault 501. Аргументы диагностического fallback не попадают в журнал запросов.

## Права обычного пользователя

Объектные методы не требуют администратора только из-за своего имени. Они проходят текущие проектные, объектные и полевые ACL. Читатель не может создавать/изменять объект или снапшот, а запрет `s_status` блокирует retire. Отдельно защищены учетные записи, системные настройки, произвольные команды и выполнение скриптов.

При check-in область записи привязана к видимому родителю. Та же проверка действует через удалённый XML-RPC и через local SDK внутри PythonCmd. Вложенный вызов восстанавливает предыдущую область прав. Автор снапшота берётся из текущей авторизации, подмена родителя/проекта не разрешена.

RetireLog записывается внутренней операцией с текущим автором и родным generated code. Это не даёт пользователю доступ к произвольному `insert('sthpw/retire_log', ...)`. Ошибка последующего действия откатывает и сам объект, и журнал.

## Транзакции и файловый откат

Пользовательские классы SObject сохраняют исходные поля конструктора `fast_data` и повторный вызов без `fast_data` при ошибке конструктора. Native TIME дополнительно передаёт `time_cols`, а кеш разрешения класса для пачки остаётся внутренним. Nullable SQL defaults без значения пропускаются: native undo/redo плагина применяет остальные defaults вместо ошибки `set_value(None)`.

Ответ браузерного Task Workspace сохраняет исходные поля задач/родителей и добавляет явные `__process__`, `__status__`, `__hours__` и родительское `__preview__` для видимых процессных контролов, сводки времени и превью. Эти дополнения проверяются отдельно от результата неизменённой процедуры ТХ.

`server.start/finish/abort` исходного SDK и local Command работают с native Transaction. Серверный Python внутри команды не открывает независимую HTTP-транзакцию для каждого вложенного вызова. Ошибка в конце сценария откатывает предшествующие изменения и создание снапшота.

FileUndo хранит собственные резервные payload в `temp/undo`, отдельно от обычного `temp/cache`: откат операции, создавшей cache-каталог, не должен удалить резервную копию. Создание каталога, перенос/копирование, замена файлов и versionless-ссылки имеют отдельные журнальные узлы. Для нескольких физических БД полный распределённый atomic commit не заявлен; ошибка частичного commit сообщается явно.

Операции с файлами разрешены только в проверенных repository/ticket путях. Режим versionless-ссылок опционален в Configuration. Он не включает Repository Sync или S3. Правила и ограничения виджетов описаны в Help **Check-in**, **Drop Plate** и **Commit Queue**.

## HTML и серверный JavaScript

Доступны `set_palette`, `get_widget`, `get_column_widgets`, `set_application_state` и `execute_js_script`. Перенесены исходные HTML/Palette/буферы, ячейки колонок, состояние top_layout и поиск JsCmd/custom_script. QuickJS-NG заменяет PyV8; серверный JavaScript доступен в Script Editor и Script Shelf.

По решению пользователя от 2026-10-11 дальнейший перенос полной старой HTML-оболочки приложения/таблиц и HTML группировки/иерархии исключён. Работающие методы и общие зависимости сохранены. Неперенесённые классы виджетов по-прежнему завершаются явной ошибкой. JS синхронный, только для администратора, без DOM/DCC/произвольных Python-объектов PyV8. Аргументы, примеры SDK, исходные особенности и границы проверок описаны в [Исходном HTML API и серверном JavaScript](help://html_api).

`commit_session` и `get_md5_info` относятся к исключённому старому production-слою. Repository Sync, S3, desktop/DCC-соединения и старые ссылки UI также не входят в перенос.

У доступных методов остаются ограничения отдельных вариантов: неподдержанные формы SQL/выражений, ещё не перенесённые зависимости удаления и виджеты. Они должны завершаться явной ошибкой до неподдержанной записи. Блок поставки проверяет SQLite, настоящий PostgreSQL 18.6 и предоставленный `cg.zip` на частных fixtures; рабочие базы пользователя не мигрирует и не сертифицирует. API `info` в виде словаря поддерживается. MySQL отложен по решению пользователя. Проверки Windows symlink пропускаются, если у тестового процесса нет права ОС создавать ссылки. См. [Установка, обновление и приёмка](help://delivery).

Некоторые исправления намеренно отличаются от исходных ошибок. Неизвестная timezone отклоняется вместо незаметного использования часового пояса машины. Read-only Select исполняется с сохранением исходного запрета типа и пустым результатом; он не получает права администратора от скопированного SQL-состояния.

## Как воспроизвести проверку

В каталоге приложения запустите `.venv/Scripts/python.exe -B -X utf8 tools/verify_api.py`. Он выполняет существующий unittest suite на приватных базах и сохраняет `.screenshots/api-block6-runtime.json`: итог тестов и счётчики успешных/отклонённых вызовов каждого метода. Аргументы, тикеты и пользовательские данные не записываются. Для отдельных тестов можно передать имена unittest-модулей.

Счётчик подтверждает, что входная точка была вызвана. Он не доказывает все ветки метода, native прямые вызовы и вызовы в дочерних процессах. `--output <файл>` позволяет сохранить отдельный отчёт и не затирать предыдущий прогон. `tools/audit_api.py` обновляет статический перечень текущих вызовов ТХ; это также не runtime-покрытие.

Тесты используют неизменённый SDK и свежие извлечённые процедуры ТХ: extended check-in, пакетный naming, редактирование/историю заметок, chat lifecycle, права и поздний откат. Восемь изменившихся исходных файлов ТХ сверены отдельно; SHA идентифицирует эталон, но сам по себе не подтверждает совпадение UI.

## Метаданные команды и привязанные ключи

`insert`, `update` и `insert_update` принимают словарь `info`. Исходный ApiXMLRPC накапливает эти метаданные и затронутые SObject в текущем запросе; ApiClientCmd передаёт их слушателям команды вместе с `function_name` и `args`. Это метаданные команды, а не дополнительные колонки БД или wire-результат метода. Следующий RPC начинает с пустого состояния. `info` другого типа отклоняется до записи объекта.

```python
row = server.insert('cg/assets', {'name': 'Prop'},
                    info={'label': 'Create prop', 'source': 'browser'})
server.update(row['__search_key__'], {'description': 'Reviewed'},
              info={'phase': 'review'})
```

`HtmlElement.generate_command_key(class_name, kwargs)` привязывает класс Command и фиксированные аргументы в ticket-каталоге текущего пользователя. `execute_cmd('$key', args, values)` объединяет аргументы вызывающего кода с привязанными: привязанные имеют приоритет; `values` заполняет исходную Web-форму. Ключ не отменяет политику доступа класса и не передаётся другому аккаунту/тикету. Классы, требующие ключ, нельзя вызвать непосредственно по имени.

`use_transaction=False` вызывает `cmd.execute()` напрямую, пропуская preprocess/postprocess/слушателей вложенной команды. Внешняя запись API **остаётся транзакционной**: поздняя ошибка откатывает её изменения. Генерируйте ключи только в доверенном серверном коде; справочник принимает существующий ключ, но не разрешает читателю создание произвольного виджета.

## Исходный SQL Delete и выражения палитры

Серверный Python может импортировать `Delete` из `pyasm.search`, как Select/Insert/Update. Поддерживаются `set_database(Sql или DbResource)`, `set_table`, `add_filter(name, value, op)` и `get_statement`. Выполнение — через `Sql.do_update(delete)` внутри авторизованной Command. Прямые записи требуют администратора и правильного ресурса; в read scope они запрещены.

```python
from pyasm.search import Delete, DbResource, DbContainer
resource = DbResource.get_default('cg_test')
delete = Delete()
delete.set_database(resource)
delete.set_table('scratch')
delete.add_filter('code', 'DEMO')
DbContainer.get(resource).do_update(delete)
```

Пример предполагает существующую временную таблицу. Для обычного удаления объектов используйте `server.delete_sobject`: прямой SQL Delete обходит SObject triggers, очистку зависимостей и FileUndo. Stream исправляет завершающий `AND` исходного builder, экранирует значения, превращает равенство None в `IS NULL` и отклоняет пустой фильтр вместо удаления всей таблицы.

`@COLOR(color)`, `@COLOR(#123456,10)`, `@PALETTE(DARK)` и `@GRADIENT(background,5,-10)` используют исходную палитру запроса. Неизвестные имена цвета сохраняют исходный fallback; это не выражения доступа к БД. Смещения/диапазоны градиента принимают литералы данных; произвольный Python исключён. Headless-вызов может создать градиент без HTTP Web adapter. Эти выражения не меняют тему Vue.

## Проверенные варианты и оставшиеся границы

| Вариант | Проверка / текущая граница |
| --- | --- |
| Словарь info, затронутые SObject, изоляция запросов | `test_api_remaining`: те же исходные тела методов и native результаты; отдельно слушатели и неверный ввод |
| Ключи команд, привязанные args, значения формы, direct mode | Те же исходные вызовы; отдельно владелец, политика разрешённого класса и поздний откат |
| SQL builder Delete | Сравнение выявляет и исправляет завершающий AND; проверки кавычек/NULL/пустого фильтра/read scope/отката |
| Выражения палитры | Одинаковые выражения в исходном runtime и Stream; опасные аргументы отклоняются |
| Удаление snapshot уровня | Настоящие файлы и строки алиасов: откат возвращает байты; удаление одного уровня сохраняет другие и default-алиасы; исправлена исходная ошибка выбора уровня |
| XML `view_as_attr` с именем | `add_config_element`/WidgetDbConfig перечитывают и переставляют `<view name="...">`, включая имя без @; это отдельно от HTML rendering |
| Остальные ветки методов | Существующие SDK/native suites проверяют чтение, записи, schema, workflow, файлы, queue, конфиг и undo; исчерпывающий паритет веток не заявлен |
| Raw-фильтры Select / serialized replacement / joins между ресурсами | Часть форм не поддерживается; подмена ресурса защищённого Search или обход ACL/read scope — граница безопасности, а не задача переноса |
| Предметные зависимости, связи выражений, события Workflow | Неподдержанные классы/типы/события завершаются ошибкой; доступный метод не означает поддержку любой предметной модели |
| Удалённые/multi-site ресурсы и распределённый commit | Не сертифицированы; локальные SQLite и PostgreSQL не означают поддержку удалённой репликации и атомарного commit между БД |
| Исполняемые Mako-конфиги виджетов | Не перенесены; декларативные XML-метаданные работают |
| QuickJS относительно PyV8 | Сохранён исходный синхронный JS client; async/DOM/DCC/произвольные Python objects исключены; исходный движок PyV8 не проверялся |
| Полная старая HTML-оболочка, S3, Repository Sync, старый production-слой | Явные исключения; работающие HTML методы сохранены |
| MySQL | Отложен; драйвер и приёмка не заявлены |

Для диагностики исходников выполните `tools/audit_api.py --contracts-output .screenshots/api9-contracts.json`. Он записывает модуль, функцию, строку и исходное сообщение каждого явного запрета UnsupportedContract. Там есть защита и согласованные исключения наряду с отсутствующими вариантами; число записей не равно числу недостающих функций и не является runtime-покрытием. Перед расширением контракта сверяйте перечень с этой матрицей и отчётом `tools/verify_api.py`.

## Браузерная консоль API и детали журнала

Консоль API сохраняет существующую авторизацию, проверку полей и явный запуск запросов. Фильтры, строки методов и поля параметров используют Frame. Закрытие отменяет загрузку каталога и очищает временные учётные данные; уже отправленная операция API может завершиться на сервере. Детали транзакций сохраняют отфильтрованный сервером XML и сообщение о скрытых записях; позднее завершение копирования не меняет другую транзакцию. Это возможности браузера, без дополнительных окон Handler.
