# Настройки задач

> Defaults задают начальное состояние задач, только если у пользователя/проекта нет сохранённого состояния.

Начальная панель выбирает Quick Tasks или Task Browser. Default браузера остаётся Task Browser; Quick Tasks доступен явно. Представление Quick Tasks выбирает карточки/компактный список. Начальный вид — Table/Gantt; сортировка — сроки/последние изменения/процесс/пользователь/статус/объект/тип/проект/приоритет/milestone/supervisor; группировка — без групп/процесс/пользователь/статус/объект. Начальные defaults: таблица, срок и группировка по процессу.

Раскрытие данных задачи задаёт начальный Task Inspector только без сохранённого выбора пользователя. Колонки Task Browser задают порядок, видимость и ширину 40–480 пикселей. Object обязателен; повторные/неизвестные ключи удаляются, новые штатные колонки добавляются. Кнопки вверх/вниз меняют те же определения, что таблица и её контекстное меню.

Сохранённые область, фильтры, колонки, раскрытие групп, календарь и выбор пользователя/проекта имеют приоритет. Отмеченные задачи и несохранённые правки не восстанавливаются. «Применить» обновляет будущую инициализацию, не заменяя текущее редактируемое рабочее пространство или его черновики.

Администратор также видит штатное планирование из XML сервера. Проектный schedule/mode важнее серверного; пустое значение оставляет даты pipeline. even/even_day/from_end_date используют штатные команды. Настройки календарного UI не выдаются за алгоритм планирования.

Владельцы: preferences.tasks, taskColumns.js, TaskManager/NotesPanel, штатные task_workspace/task_schedule и ServerConfiguration. Сброс/применение задач сохраняет XML-черновики репозиториев/сервера.
