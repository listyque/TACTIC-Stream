# Внутренняя структура: контекст Site

> Исходный провайдер Site текущей установки, его контекст выражений и ограничения. Именованным сайтам и внешним провайдерам ещё нужны native изоляция баз и маршрутизация.

## Site, проект и адрес браузера

`Site` описывает контекст установки. Это отдельное понятие от проекта, пользователя и имени сервера в браузере. При выборе `cg_test` поле `Site.code` не становится равным `cg_test`.

Поддержан исходный контекст установки без имени: его код — пустая строка. Провайдер экспортируется из `pyasm.security`; реализация находится в `pyasm/security/security.py`. Он сообщает исходный виртуальный search type и проект `admin`, не создавая строку или таблицу в БД.

```python
from pyasm.security import Site
from pyasm.biz import ExpressionParser

site = Site.get()
site.get_value('code')                       # ''
Site.get_site()                             # ''
ExpressionParser().eval('@GET(site.code)')   # ['']
ExpressionParser().eval('@GET(site.code)', single=True)  # ''
Site.get_site_data('')                      # {}
```

Неизвестные поля провайдера возвращают `None`. Провайдер не является обычным сохраняемым SObject; не пытайтесь получить или сохранить его как запись БД. Native значение `get_id()` — `-1` — нужно только для идентичности в кэше выражений. Оно исправляет исходную ошибку `@GET(site.code)` при пустом коде и не обозначает id сохранённой строки.

## Выражения, скрипты и передача через API

Один провайдер работает в контексте выражения `site`, как начальный объект, как явно переданный environment-объект и в шаблонах Naming. Существующий API проверяет вложенный доступ к `sthpw/virtual` перед вычислением контекста.

```python
# Исходный XML-RPC клиент
server.eval('@GET(site.code)')   # ['']

# Серверный Python
from pyasm.security import Site
result = {'site_code': Site.get().get_value('code')}
```

Локальный `@SOBJECT(site)` возвращает экземпляры провайдера Site. API `eval('@SOBJECT(site)')` явно отказывает в передаче их как записей: исходное XML-RPC представление содержало нестабильный адрес Python-объекта. Читайте поля через `@GET` или возвращайте обычные словари из серверного Python. Этот отказ не относится к настоящим виртуальным SObject, например `state` и `date`.

## Конфигурация и безопасность

| Вызов или настройка | Поведение в поддержанном контексте без имени |
| --- | --- |
| `Site.get_default_project()` / `get_user_project()` | Читают `install.default_project`, не подставляют текущий выбранный проект. |
| `security.site_class` | Не задана либо содержит один из путей базового класса: `pyasm.security.Site` / `pyasm.security.security.Site`. |
| `get_connect_data('')` / `get_site_data('')` | Пустые словари, как у исходного базового провайдера. |
| Hooks путей asset/web, гостя и аутентификации | Сохраняют пустые значения базового провайдера; не выбирают repository и не выдают гостевой доступ. |
| `build_ticket(ticket)` / `validate_ticket(ticket)` | Базовые точки расширения: сохраняют значение / возвращают `True`. Они не проверяют аутентификацию. |

Настоящая аутентификация API продолжает проверять сохранённые tickets, владельца и срок действия через Security. Поддельный ticket не становится действительным из-за `True` в базовом hook. Серверный Python остаётся доступен только разрешённым пользователям.

В исходном объявлении `get_site_data` отсутствовал декоратор classmethod. Stream разрешает предполагаемый вызов через класс и сохраняет вызов через экземпляр; исходная ошибка и native исправление проверены отдельно.

## Неподдержанные сайты и проверки

Выбор непустого site, именованные подключения, запуск, регистрация и фабрики внешних провайдеров дают `UnsupportedContract`. Stream не направляет другой сайт в текущую базу молча и не подменяет сломанный внешний провайдер базовым. Именованный выбор отклоняется до изменения текущих Security и стека сайтов. Если он следует за записью в БД внутри Command, отказ откатывает эту запись.

Это не завершённая поддержка нескольких сайтов и не интеграция внешних провайдеров в аутентификацию. Старые HTML-виджеты и URL-маршрутизация `TacticSite` не входят в блок. Адреса проектов в браузере существуют отдельно от провайдера Site.

С фактическим исходным runtime сравнены 37 сценариев: базовые hooks, выражения, начальные и environment-объекты, Naming и отказы. Ошибки исходника имеют отдельные исходные и native ожидания. Также проверены неизменённый XML-RPC SDK, серверный Python, восстановление access policy, недействительные tickets и откат на SQLite и отдельной PostgreSQL БД. Тесты: `tests/test_expression_site.py` и `tests/test_expression_paths.py`.
