# Исходный HTML API и серверный JavaScript

С 0.112.39 доступны пять ранее отсутствовавших входных точек. В каталоге теперь 127 доступных методов и два исключения. Это покрытие входных точек, **не полный паритет поведения**. Интерфейс браузера остаётся на Vue; исходный HTML — отдельный контракт SDK.


Дальнейший перенос полной старой HTML-оболочки/таблиц и HTML группировки/иерархии исключён по решению пользователя от 2026-10-11. Работающие методы и их общие зависимости сохранены. Исходные XML-метаданные и серверный JavaScript остаются частью поддерживаемого ядра.

## HTML виджетов

`get_widget(class_name, args={}, values={}, libraries={}, interaction={})` возвращает HTML-строку перенесённого класса `Widget`. `args` — параметры конструктора, `values` — значения формы запроса. Нужны права администратора. Вызов выполняется внутри исходного Command: изменения конструктора откатываются при ошибке рендеринга. Базовые HTML-элементы, контейнеры, таблицы и наследники `BaseRefreshWdg` используют исходные буферы и описания behaviors.

```python
html = server.get_widget('pyasm.web.HtmlElement',
    {'type': 'span', 'child': 'Hello'})
```

Это доверенный серверный HTML. Stream не вставляет произвольные старые виджеты в Vue и не добавляет автоматически старый клиентский framework. Неперенесённые классы, интерактивная оболочка TableLayout, старая оболочка приложения и библиотека `spt_help` завершаются явной ошибкой. Аргумент `interaction` сохраняет исходное поведение: он не используется. `libraries` регистрирует метаданные библиотек в запросе, не устанавливая отсутствующие JS-зависимости.

В «Конфигурация → Конфигурация сервера → Безопасность» доступна настройка `api_widget_restricted`. Она применяет исходные правила `builtin` и проверяет привязанные аргументы `$widget_key`. Ключ принадлежит текущему пользователю и хранится в проверенной папке его тикета. Настройка не разрешает обычному пользователю выполнять доверенный HTML.

## Палитра запроса

`set_palette(palette)` помещает палитру в исходный стек Palette текущего серверного запроса и возвращает `None`. Поддерживаются имена (`DARK`, `LIGHT`, `DEFAULT`) и словарь цветов. Сохраняется исходный порядок настроек проекта, пользователя и конфигурации. Python-выражения запрещены: настройки разбираются как данные.

Отдельный XML-RPC вызов сразу заканчивает запрос и не сохраняет палитру для последующих RPC. Для рендеринга с палитрой используйте один серверный Python-скрипт и локальный SDK:

```python
from pyasm.web import Palette
server.set_palette('DARK')
try:
    return server.get_widget('pyasm.web.DivWdg')
finally:
    Palette.pop_palette()
```

Тема браузера настраивается отдельно. Буферы HTML, палитры, WebState и JS-контекст принадлежат запросу и не перетекают между параллельными вызовами.

## HTML колонок

`get_column_widgets(ticket, search_type, search_keys, element_name)` возвращает вложенный список: по строке на объект, внутри — HTML `<td>` выбранной колонки. Используются исходная table-конфигурация, атрибуты ячеек, hooks оформления, color maps и перенесённые display handlers. Неподдержанный обработчик даёт ошибку. DTO метаданных не подменяет HTML.

Исходный метод пропускает первый insert-ключ с `id=-1` и загружает объекты, только если осталось **больше одного ключа**. Поэтому один ключ возвращает `[]`; это поведение сохранено. Отсутствующие или недоступные строки дают ошибку. HTML группировки/иерархии и полная интерактивная оболочка таблицы ещё не перенесены.

У исходного Python SDK нет удобного метода для этого вызова; используйте XML-RPC proxy:

```python
cells = server.server.get_column_widgets(server.ticket,
    'cg/assets', [first_key, second_key], 'name')
```

## Состояние приложения

`set_application_state(ticket, key, panel_name, widget_class, options, values={})` поддерживает исходный `key='top_layout'`. Метод разрешает настроенный `top_class_name`, обновляет раздел исходной XML-конфигурации и сохраняет пользовательский WidgetSettings выбранного проекта. Результат — `True`. Строковые значения и вложенные options сохраняются; нестроковые значения формы пропускаются, как в исходнике. Исправлены исходная ошибка вложенных options и создание записи при сохранении.

```python
server.server.set_application_state(server.ticket, 'top_layout',
    'main_body', 'pyasm.web.DivWdg', {'title': 'Example'}, {})
xml = server.server.get_widget_setting(server.ticket, 'top_layout')
```

Здесь нужен proxy: исходный Python SDK не содержит `set_application_state`, а его helper `get_widget_setting` рекурсивно вызывает сам себя. Раскладки веб-доков сохраняются собственным механизмом; этот API их не меняет. Сохранение класса ещё не перенесённого виджета не делает доступной его старую HTML-оболочку.

## Серверный JavaScript

В Script Editor появился **Серверный JavaScript**, сохраняемый с `language='server_js'`. Script Shelf умеет запускать эти сохранённые скрипты. Браузерный `javascript` остаётся отдельным режимом.

`execute_js_script(script_path, kwargs={})` использует исходный JsCmd и поиск custom_script. Путь выбирает `folder/title` и имеет приоритет над `kwargs.code`; `file_path` — доверенный серверный путь администратора. Каждый параметр kwargs становится JS-глобальной переменной. Исходный JS SDK доступен через `server`, с текущими login, project, правами API и транзакцией Command.

```javascript
var note = server.insert('sthpw/note', {note: input.text});
return {key: note.__search_key__, ping: server.ping()};
```

```python
result = server.execute_js_script('', {
    'code': "return {ping: server.ping(), value: input.value};",
    'input': {'value': 7},
})
# {'status': 'OK', 'description': '...', 'info': {...}}
```

QuickJS-NG заменяет устаревший PyV8; исходные JS SDK и поиск команды сохранены. Выполнение синхронное: Promise и циклические результаты запрещены. Отсутствие return даёт `info=None`. Необработанная ошибка откатывает записи API и показывает источник `tactic://project/script`; перехваченная ошибка API остаётся обычной JS-ошибкой. `console.log` пишет в серверный журнал.

Серверный JavaScript доступен только администратору и является доверенным кодом, не песочницей. Нет DOM браузера, подключения к DCC, асинхронного event loop и произвольного взаимодействия с Python-объектами PyV8. Bridge передаёт JSON и не предоставляет файловые bindings. Исходные callbacks PythonTrigger с языком `server_js` используют ту же команду и транзакцию.

## Проверки и границы

`test_html_api` проверяет неизменённый SDK/XML-RPC, права, изоляцию запросов, откат, сохранённые пути, ячейки и состояние раскладки. `test_html_parity` выполняет одинаковые операции HTML/палитры в исходном embedded runtime и Stream. Старый PyV8 не запускается; новый движок проверяется с исходным JS-клиентом и настоящими вызовами native API. Оставшиеся варианты и исключения описаны в [Совместимости ядра и API](help://api_compatibility).
