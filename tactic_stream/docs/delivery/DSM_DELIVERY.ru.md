# TACTIC Stream на Synology DSM

Пакет `.spk` устанавливает Stream, Apache и PostgreSQL через Container Manager.
Образы Linux уже внутри: скачивать зависимости приложения при установке не нужно.
Нужны **NAS с процессором x86-64, DSM 7.2.1 или новее и Container Manager**.
Модели NAS на ARM этим пакетом не поддерживаются.

Это **предварительная сборка для новой установки**. Для Compose и установочных
скриптов есть автоматические проверки; установку через Package Center на настоящем
Synology ещё предстоит проверить. Пакет отказывается обновлять существующую установку
или использовать оставшиеся данные. Действующий сервер оставьте отдельно до проверки
миграции на копии его резервной копии.

## Установка

1. Скачайте чистый или демонстрационный SPK со страницы [Releases](https://github.com/listyque/TACTIC-Stream/releases).
2. В Package Center выберите Manual Install и укажите SPK.
3. Выберите свободный HTTP-порт и задайте новый пароль администратора. Логин — `admin`.
4. Запустите пакет. Container Manager создаст базу; демо-версия также создаст проекты
   и опубликует картинки. Дождитесь окончания первого запуска.
5. Откройте ярлык пакета или `http://адрес-NAS:порт/`.

По умолчанию чистая версия использует порт **8882**, демо — **8884**. У них разные
имена пакетов и Docker-проектов, поэтому их можно установить рядом. Чистая версия
начинает без рабочих проектов. В демо есть Orbit Studio и Atlas Reference Library:
картинки с версиями, задачи, пользователи, workflow, база знаний и два примера плагинов.
Сначала войдите администратором. Сгенерированные пароли демо-пользователей находятся в
`/var/packages/TacticStreamDemo/var/data/stream/demo-accounts.json`.

В Handler укажите HTTP-адрес NAS и войдите отдельно. Пакет DSM не устанавливает
настольный клиент на NAS.

## Данные и доступ

Наружу открыт только HTTP-порт приложения. PostgreSQL, серверные процессы и Webmin
не получают открытых портов NAS. Для HTTPS используйте DSM Reverse Proxy, а доступ
к HTTP-порту ограничьте доверенной сетью. Пакет не меняет брандмауэр NAS, маршрутизатор,
сертификаты, существующие общие папки или чужие Docker-проекты.

Файлы проектов, конфигурация сервера и данные PostgreSQL лежат в
`/var/packages/TacticStream/var/data` (для демо — `TacticStreamDemo`). Пароли служб —
в соседней закрытой папке `secrets`. Конфигурация Apache/Webmin хранится в томах
Docker-проекта пакета. Скрипты установки работают от пользователя пакета, контейнерами
управляет Container Manager. Инициализация использует root внутри контейнера только
для подготовки своей папки данных, затем переключается на пользователя Stream.

Перед холодной резервной копией остановите пакет. Сохраните всю постоянную папку `var`
вместе с томами Apache/Webmin. Остановка и удаление пакета не запускают очистку данных.
Повторная установка отказывается использовать оставшиеся данные; для восстановления
нужны соответствующие друг другу база, репозиторий и пароли служб. Установка старого
SPK сама по себе не откатывает базу.

## Сборка

Сначала соберите [Docker-поставку](https://github.com/listyque/TACTIC-Stream/wiki/Server-ru), затем из `tactic_stream`:

```sh
python -m tools.dsm_delivery --server /path/to/server-package --output /path/to/TACTIC-Stream-DSM.spk
```

Сборщик проверяет контрольные суммы исходного пакета, сохраняет его вариант clean/demo
и записывает SHA-256 рядом с SPK. Используются штатные
[Docker Project Worker](https://help.synology.com/developer-guide/resource_acquisition/docker-project.html)
и [окружение пакета DSM](https://help.synology.com/developer-guide/synology_package/script_env_var.html).
